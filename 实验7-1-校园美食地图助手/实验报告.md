## 三、实验原理

### 3.1 Vibe Coding

用自然语言描述目标，由 AI 生成可运行代码。适合个人快速探索，缺点是需求边界模糊、代码风格不统一。

### 3.2 MCP 与 REST API 的关系

实验要求在 `mcp_settings.json` 中配置高德 MCP 服务：

```json
{
  "mcpServers": {
    "amap-maps": {
      "command": "npx",
      "args": ["-y", "@amap/amap-maps-mcp-server"],
      "env": { "AMAP_MAPS_API_KEY": "你的高德Key" }
    }
  }
}
```

MCP 工具本质是对高德服务的封装。由于 HTML 页面运行在浏览器中，无法直接调用 MCP 工具，因此按能力拆分实现：

**REST 接口（搜索与路线）**

- POI 搜索：`https://restapi.amap.com/v3/place/text`
- 步行路线：`https://restapi.amap.com/v3/direction/walking`

**JS API 插件（定位与地图）**

- 城市识别：`AMap.CitySearch`（校园网 IP 识别当前城市）
- 定位：`AMap.Geolocation`，参数 `citylimit: true` 将结果限制在校园所在城市，避免校园网 IP 漂移
- 逆地理编码：`AMap.Geocoder` 获取详细地址
- 地图底图：`AMap.Map` + `AMap.Marker` + `AMap.InfoWindow`

> 定位不再调用 `https://restapi.amap.com/v3/ip`。浏览器定位需要 JS API Key + 安全密钥，并在 localhost / HTTPS 环境下允许定位权限；失败时自动降级到演示位置。

### 3.3 SKILL 固化规则

把推荐策略写成 SKILL 文档（见 `skill/food-recommender/SKILL.md`），后续对话时 AI 自动检索并加载这些规则，无需每次重复描述。

## 四、实验步骤与实现

### 任务一：创建项目与配置高德 MCP

1. 新建项目 `campus-food-map-assistant`。
2. 在高德开放平台完成个人开发者认证，创建应用 `food-map`，申请 **Web 服务** Key（POI 搜索与路线）。
3. 在码道 MCP 配置页打开 `mcp_settings.json`，配置 `@amap/amap-maps-mcp-server`。

> 定位与地图依赖 JS API，因此额外申请 **Web 端（JS API）Key + 安全密钥 securityJsCode**，用于 `AMap.Geolocation`（`citylimit`）与地图底图。

### 任务二：用 SKILL 固化美食推荐规则

创建 `food-recommender` 技能，规则包括：

- 距离 < 1km 优先
- 价格三档：平价 < 30、中档 30-80、高档 > 80
- 口味六类：川菜、粤菜、日料、西餐、小吃、奶茶
- 评分 > 4.0 优先
- 输出：名称 | 距离 | 人均 | 口味 | 评分 + 一句推荐理由

#### 第三轮：Bug 修复与性能优化

**问题 1：距离显示 0m**

原因：详情卡片依赖 POI 返回的单一 `distance` 字段，部分场景该字段为空或为 0。

修复：优先读取接口 `distance`，无效时用 Haversine 公式根据双方经纬度计算，并统一格式化（米/公里）。

```js
const haversine = (a, b) => {
  const R = 6371000, rad = Math.PI / 180;
  const dLat = (b.lat - a.lat) * rad;
  const dLng = (b.lng - a.lng) * rad;
  const s = Math.sin(dLat / 2) ** 2 +
    Math.cos(a.lat * rad) * Math.cos(b.lat * rad) * Math.sin(dLng / 2) ** 2;
  return 2 * R * Math.asin(Math.sqrt(s));
};

const formatDistance = (meters) => {
  if (!Number.isFinite(meters) || meters <= 0) return '—';
  return meters >= 1000 ? `${(meters / 1000).toFixed(1)}km` : `${Math.round(meters)}m`;
};
```

**问题 2：地图缩放卡顿**

修复：增加性能参数并采用分批渲染。

```js
new AMap.Map('map', {
  zoom: 14,
  center: [lng, lat],
  zooms: [12, 18],
  enableHighResolution: false,
  fadeEffect: false,
  viewMode: '2D'
});

const renderBatch = () => {
  list.slice(cursor, cursor + 8).forEach((item) => { /* 创建 Marker */ });
  cursor += 8;
  if (cursor < list.length) requestAnimationFrame(renderBatch);
};
```

## 五、关键实现说明

### 5.1 状态驱动

所有交互共享一个 `state`：位置、结果集、筛选条件、排序方式、选中项、地图实例、标记集合。任何交互只改状态，再统一渲染列表与标记，避免列表和地图不同步。

### 5.2 校园网定位（AMap.Geolocation）

```js
AMap.plugin(['AMap.CitySearch', 'AMap.Geolocation'], () => {
  const citySearch = new AMap.CitySearch();
  citySearch.getLocalCity((cityStatus, cityResult) => {
    const city = cityResult.city;
    const geolocation = new AMap.Geolocation({
      enableHighAccuracy: true,
      timeout: 10000,
      city,
      citylimit: true,
      GeoLocationFirst: true
    });
    geolocation.getCurrentPosition((status, result) => {
      if (status === 'complete') applyLocation(result.position.lng, result.position.lat, result.formattedAddress);
    });
  });
});
```

流程：`AMap.CitySearch` 先识别校园网所在城市 → `AMap.Geolocation` 以 `citylimit: true` 把定位结果限制在该城市内 → `AMap.Geocoder` 逆地理编码补全详细地址。相比 IP 定位，浏览器定位精度更高，且校园网跨运营商场景下不会漂移到其他城市。

### 5.3 数据归一化

高德 POI 字段存在数组与字符串混用（如 `biz_ext.rating`、`biz_ext.cost`、`distance`），统一用 `Array.isArray(x) ? x[0] : x` 解析后再转数字，缺失时给默认值。

### 5.4 口味推断

高德不直接返回“川菜/奶茶”这类分类，用名称与 `type` 关键字正则匹配推断，覆盖六类口味。

### 5.5 降级策略

- 未配置 Key：使用内置 12 条演示数据，全部功能仍可体验。
- 接口失败：自动切回演示数据并提示用户。
- 路线接口失败：退化为直线距离估算。
- 定位失败（无 JS API Key、未授权、非 localhost/HTTPS）：使用演示位置并提示。

### 5.6 Key 安全

Key 不写入代码，只存浏览器 `localStorage`。仓库中不包含任何真实 Key，上传 GitHub 无泄露风险。

## 七、问题与修复记录

| 问题 | 现象 | 原因 | 修复 |
| --- | --- | --- | --- |
| 距离显示 0m | 所有卡片距离为 0 | 依赖单一 `distance` 字段 | 增加 Haversine 兜底计算 |
| 地图缩放卡顿 | 缩放有延迟、掉帧 | 高分辨率 + 动画特效 + 一次性渲染大量标记 | 关闭高分辨率与特效、限制缩放级别、分批渲染 |
| 定位失败 / 落到演示位置 | 未配 JS API Key、未授权浏览器定位、非 localhost/HTTPS | 校园网定位依赖 JS API 与浏览器权限 | 配置 JS API Key 和安全密钥；用 localhost/HTTPS 打开并允许定位；失败自动降级演示位置 |
| 接口无结果 | 某些关键词返回空 | 城市限制 + 关键词过窄 | `citylimit` 可关闭、提供快捷标签与空结果提示 |
| 评分/人均缺失 | 部分 POI 无 `biz_ext` | 数据源未收录 | 按口味给保守默认值，界面标注参考值 |

## 八、实验总结

1. **多轮对话优于一次性给全需求**。把“基础框架 → 增强功能 → 修复优化”拆成三轮，每轮都能验证，问题定位更清晰。
2. **SKILL 的价值在于复用**。推荐规则写一次，后续对话自动生效，输出格式稳定。
3. **真实数据必须做降级**。网络、Key、配额任一环节都可能失败，Mock 数据保证演示不中断。
4. **性能优化要落到参数**。关闭高分辨率、限制缩放、分批渲染，是地图类页面最直接有效的手段。

通过本实验，完成了一个可运行、可演示、可维护的校园美食地图助手，并完整走通了 Vibe Coding 的开发闭环。
