### 第二轮新增/重构模块

| 模块 | 类型 | 职责 |
| --- | --- | --- |
| `Validator` | 新增 | 餐厅 ID、关键词、收藏项结构校验 |
| `XSSFilter` | 新增 | 存储前危险内容剥离 |
| `escapeHtml` | 增强 | 渲染前统一转义 |
| `readFavorites` | 重构 | 增加结构校验与非法项过滤 |
| `readRecentSearches` | 重构 | 增加净化与截断 |
| `toggleFavorite` | 重构 | 接入校验与过滤 |
| `bindEvents` | 重构 | 统一事件委托与 `addEventListener` |

### 规范约束前后对比

| 维度 | 第一轮（能跑就行） | 第二轮（可交付） |
| --- | --- | --- |
| ID 校验 | 无，任意值可写入 | 必须 string 且非空，否则 `console.warn` |
| XSS 防护 | 直接拼接 HTML | 存储过滤 + 渲染转义双层防护 |
| 关键词 | 原样记录 | 过滤、去重、限长 40、限 8 条 |
| 代码风格 | 混用 `var`/`let`，无注释 | 全 ES6，函数均有 JSDoc，驼峰命名 |
| 事件绑定 | 部分内联 `onclick` | 全部 `addEventListener` |
| 可维护性 | 逻辑分散 | 规则层、数据层、视图层分离 |

## 三、任务执行说明

1. **任务粒度**：每个子任务对应一处可独立验证的代码改动，完成后可立即回归。
2. **依赖关系**：规则层（R4、R5）必须先于业务接入（R6、R7、R8），否则会出现“边写边漏”的约束缺口。
3. **验收方式**：对照 `spec.md` 的验收标准逐条勾选，并补充规范约束专项用例。
4. **归档原则**：代码与规格同仓保存，后续修改功能时先改规格再改代码。
