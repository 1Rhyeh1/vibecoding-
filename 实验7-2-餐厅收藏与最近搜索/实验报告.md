## 三、实验原理

### 3.1 为什么需要规格书

Vibe Coding 适合一个人快速探索，但项目一旦要交付、协作、长期维护，就会暴露问题：

- 同一个“收藏”需求，不同人让 AI 实现，会得到不同的图标、不同的存储位置、不同的刷新行为。
- 没有验收标准，就无法判断“做完了没有”。
- 没有约束条件，代码“能跑”但不可靠。

### 3.2 规格书四要素

| 要素 | 作用 | 本实验示例 |
| --- | --- | --- |
| 功能描述 | 说清楚做什么 | 卡片显示收藏图标，点击收藏/取消 |
| 输入 | 定义参数与类型 | 餐厅 ID：string，必填 |
| 输出 | 定义可观察结果 | 实心/空心图标、toast 文案、面板展示 |
| 约束条件 | 定义边界与规则 | 最多 20 家、localStorage 持久化、不可重复 |
| 验收标准 | 定义可验证清单 | 刷新保持、超限提示、点击定位 |

### 3.3 SDD 四步法

```
提交规格书 → 需求规格设计 → 实现方案设计 → 编码任务规划 → 任务执行 → 审查验收 → 归档
```

规范驱动模式下，AI 不会直接写代码，而是先生成 `spec.md`、`design.md`、`tasks.md`，确认后再按任务顺序生成代码。

## 四、实验步骤

### 任务一：体验“无规格”的痛点

在探索模式（Vibe-Coding Mode）下直接输入：

> 帮我加一个餐厅收藏功能。

观察结果：

| 维度 | 可能出现的不一致 |
| --- | --- |
| 图标 | ❤️ / ★ / ☆ / 书签，各人不同 |
| 存储 | localStorage / sessionStorage / 内存 |
| 刷新行为 | 有的保持，有的丢失 |
| 上限 | 有的不限制，有的 10 家、50 家 |
| 交互 | 有的弹窗提示，有的静默 |

结论：无规格时 AI 按自己的理解实现，团队协作会得到多套不兼容的版本。因此本次代码迭代先“全部拒绝”，改用规范驱动模式。

## 五、关键实现说明

### 5.1 校验规则

```js
const Validator = {
  isValidRestaurantId(id) {
    const valid = typeof id === 'string' && id.trim().length > 0;
    if (!valid) console.warn('[Validator] 非法餐厅 ID，操作已忽略：', id);
    return valid;
  }
};
```

所有收藏、取消收藏、定位入口先调用校验，非法值直接返回，不产生任何写操作。

### 5.2 XSS 双层防护

**存储前过滤**

```js
const stripDangerous = (value) => String(value == null ? '' : value)
  .replace(/<\s*script[\s\S]*?<\s*\/\s*script\s*>/gi, '')
  .replace(/<\s*\/?\s*(iframe|object|embed|link|style|meta|base)\b[^>]*>/gi, '')
  .replace(/\son\w+\s*=\s*("[^"]*"|'[^']*'|[^\s>]+)/gi, '')
  .replace(/javascript:/gi, '');
```

**渲染前转义**

```js
const escapeHtml = (value) => String(value == null ? '' : value).replace(/[&<>"']/g, (char) => ({
  '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;'
})[char]);
```

为什么两层都要：只存不转义，接口数据仍有风险；只转义不过滤，恶意内容会长期驻留本地存储。

### 5.3 收藏持久化

```js
const readFavorites = () => {
  try {
    const raw = localStorage.getItem(STORAGE.favorites);
    if (!raw) return [];
    const parsed = JSON.parse(raw);
    if (!Array.isArray(parsed)) return [];
    return parsed
      .filter((item) => Validator.isValidFavorite(item))
      .slice(0, MAX_FAVORITES)
      .map((item) => XSSFilter.sanitizeRestaurant(item));
  } catch (error) {
    console.warn('[Favorites] 读取收藏失败', error);
    return [];
  }
};
```

读取时校验结构并截断，防止手动篡改导致渲染异常。

### 5.4 收藏上限与去重

```js
if (index >= 0) {
  state.favorites.splice(index, 1);
  toast('已取消收藏');
  return;
}
if (state.favorites.length >= MAX_FAVORITES) {
  toast(`收藏夹已满（最多${MAX_FAVORITES}家）`);
  return;
}
```

### 5.5 最近搜索

```js
const addRecentSearch = (keyword) => {
  const term = XSSFilter.sanitizeKeyword(keyword);
  if (!term) return;
  state.recentSearches = [term, ...state.recentSearches.filter((item) => item !== term)]
    .slice(0, MAX_RECENT_SEARCHES);
  writeRecentSearches(state.recentSearches);
  renderRecentSearches();
};
```

新关键词置顶，去重，截断 8 条。

### 5.6 校园网定位（AMap.Geolocation）

定位不再调用 `/v3/ip`，改为高德 JS API 插件组合：

1. `AMap.CitySearch` 获取校园网所在城市；
2. `AMap.Geolocation` 设置 `citylimit: true`，把定位结果限制在该城市内；
3. `AMap.Geocoder` 逆地理编码补全详细地址。

```js
AMap.plugin(['AMap.CitySearch', 'AMap.Geolocation'], () => {
  const citySearch = new AMap.CitySearch();
  citySearch.getLocalCity((cityStatus, cityResult) => {
    const city = cityResult.city;
    const geolocation = new AMap.Geolocation({
      enableHighAccuracy: true,
      timeout: 10000,
      city,
      citylimit: true,
      GeoLocationFirst: true
    });
    geolocation.getCurrentPosition((status, result) => {
      if (status === 'complete') applyLocation(result.position.lng, result.position.lat, result.formattedAddress);
    });
  });
});
```

定位依赖 JS API Key 与安全密钥，并要求在 localhost 或 HTTPS 下允许浏览器定位；任一条件不满足时自动降级到演示位置。

### 5.7 收藏定位

收藏只保存坐标，展示时实时计算距离。点击收藏项时优先复用当前结果中的餐厅对象，找不到则用收藏数据构造临时对象，保证地图定位与信息窗体可用。

## 六、规范约束前后对比

| 维度 | 第一轮（能跑就行） | 第二轮（可交付） |
| --- | --- | --- |
| ID 校验 | 无 | string 且非空，否则拒绝并 `console.warn` |
| XSS | 直接拼 HTML | 存储过滤 + 渲染转义 |
| 关键词 | 原样记录 | 过滤、去重、限长 40、限 8 条 |
| 收藏读取 | 直接 `JSON.parse` 使用 | 结构校验、截断、异常兜底 |
| 代码风格 | 混用声明方式、无注释 | 全 ES6、全 JSDoc、驼峰 |
| 事件绑定 | 部分内联 | 全 `addEventListener` |
| 可维护性 | 逻辑分散 | 规则层、数据层、视图层分离 |

## 八、问题与修复记录

| 问题 | 现象 | 原因 | 修复 |
| --- | --- | --- | --- |
| 收藏点击误触卡片 | 点收藏后列表跳转 | 事件冒泡到卡片 | 收藏按钮单独判断并 `stopPropagation` |
| 收藏刷新丢失 | 刷新后收藏为空 | 只存内存未持久化 | 写入 `localStorage` 并在启动时读取 |
| 上限不生效 | 可无限收藏 | 未校验数组长度 | 写入前判断 `MAX_FAVORITES` |
| 历史重复堆积 | 同一关键词出现多次 | 未去重 | 过滤同值后置顶 |
| 读取脏数据崩溃 | 手动改 localStorage 后白屏 | 未校验结构 | 读取时逐项校验并 `try/catch` |
| 收藏项点击不定位 | 该餐厅不在当前搜索结果 | 只从结果集查找 | 用收藏数据构造临时对象 |
| 地图缩放卡顿 | 标记多时掉帧 | 一次性渲染 | 分批渲染 + 性能参数 |
| 校园网定位失败 | 位置落到默认演示点 | 未配 JS API Key、未授权定位、非 localhost/HTTPS | 改用 `AMap.Geolocation` + `citylimit`，失败自动降级并提示 |
| 安全约束遗漏 | 部分渲染点未转义 | 约束添加前已写死拼接 | 统一 `escapeHtml` 并逐处替换 |

## 九、实验总结

1. **SDD 把“会写代码”变成“能交付代码”**。规格书明确了输入输出与验收标准，AI 生成结果可验证、可对比。
2. **约束应当集中实现**。Validator 与 XSSFilter 独立成模块后，新增入口只需复用，不会出现“这里校验了、那里忘了”。
3. **先功能后约束是合理路径**。功能未定型时过度设计会拖慢进度；跑通后统一加固，改造点清晰。
4. **安全要做双层**。存储过滤防持久化污染，渲染转义防执行，缺一不可。
5. **归档让规范成为资产**。规格、方案、任务与代码同仓，后续维护者能看懂“为什么这么设计”。

一句话总结：Vibe Coding 让你“写得快”，SDD 让你“交得稳”。
